Forms can now take several files in one field: photos of a venue, a set of plans, a brief and its appendices. Every file is attached to the email and none is kept on the site. Forms with a single file field, or without any, work exactly as before.

## What changes

- **Fields taking several files.** Write `[attachment files]` (optional) or `[attachment* files]` (at least one file) in an email template. The visitor can pick files in several goes: each selection adds to a list, a file already in it is ignored, and each file can be removed from the list before sending. The mail content shows the file names, separated by commas. **Generate form template** writes the input and the list for you.
- **Maximum number of files.** The **File uploads** row of each template has a new **Maximum number of files** setting (3 by default, up to 20, never more than the server takes in one request). It applies to each field taking several files; the allowed formats and the maximum size keep their meaning, per file. The line telling visitors what is accepted says so: *Formats : JPG, PNG, PDF — 5 Mo maximum par fichier, 3 fichiers maximum*.
- **File settings only where they apply.** On the template screen, the **File uploads** row now only shows when the template has a file placeholder, and **Maximum number of files** only with a `files` one. Both appear or disappear as you type or remove a placeholder, before saving; hidden settings keep their values.
- **Every file checked.** Each file goes through the same checks as a single file (size, extension, real content), and the server refuses more files than allowed. A refused file is named in the message, so the visitor knows which one to replace. The visitor's browser checks the format, the size and the number of files first.
- **Nothing kept on the site.** As for single files, each file only exists for the time it takes to send the email, in a private temporary folder of its own, and is deleted right after, sent or not. Received messages only keep the file names, and **Send the email again** sends the email without the files.

## Updating

From the WordPress admin: Plugins → update "LCMT Mailer". Existing forms are not affected: single file fields, forms without files, the spam protection and received messages behave as before.

To let a form take several files: add `[name files]` to the template, check its **File uploads** row (including **Maximum number of files**), then add `<input type="file" name="name[]" multiple>` and, to show the chosen files, `<ul data-lcmt-file-list="name"></ul>` to the theme's form file (see the README, *File fields*). Make sure the server's `post_max_size` is larger than the number of files times the maximum size. If you use a page cache, purge it after updating so that pages load the new form script.

## For developers

- New placeholder type `files` (TypeScript type `File[]`). Its files are posted as `name[]` and arrive in `$_FILES['name']` in PHP's array shape; `FileField::checkMany()` checks them, one by one, with the same logic as `FileField::check()`.
- New theme helper `lcmt_mailer_file_max_files($key)`. `lcmt_mailer_file_hint($key)` adds "per file" and the number of files when the template has a `files` field, and is unchanged otherwise.
- The `<form>` of a template with a `files` field also gets `data-lcmt-file-max-files`. The list element `[data-lcmt-file-list="<field>"]` gets one `<li>` per file (the name and a `<button type="button" data-lcmt-file-remove>` labelled *Remove plan.pdf*) and `data-lcmt-file-chosen` while it is not empty.
- `lcmt_mailer_file_limits` now passes and accepts `max_files`; a filter that does not return it keeps the template's value.
- New post meta `_lcmt_mail_file_max_files` (`MetaFields::FIELD_FILE_MAX_FILES`), copied to translations.
