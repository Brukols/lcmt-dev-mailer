# ALTCHA v3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the ALTCHA protection to widget 3.5.0 and its new proof of work (PBKDF2, with a difficulty the site owner chooses), so that each spam submission costs a bot real computing time, for LCMT Mailer 2.8.0.

**Architecture:** The widget (npm `altcha` 3.5.0, bundled into `assets/dist/captcha-altcha.js`) solves a PBKDF2/SHA-256 challenge in Web Workers. The PHP side issues and checks those challenges itself (`hash_pbkdf2`, `hash_hmac`), with no new PHP dependency, replacing the SHA-256 "v1" format. The difficulty (PBKDF2 iterations + key prefix length) is a setting of the ALTCHA tab.

**Tech Stack:** PHP 8.1+ (the plugin's floor, `Requires PHP` in `lcmt-dev-mailer.php`), WordPress REST API, esbuild, `altcha` 3.5.0, PHPUnit, `node:test`.

**Spec:** this conversation's decisions (owner, 2026-11-01): "update ALTCHA", difficulty adjustable, tested by the owner on another site. The protocol reference is ALTCHA's own source at tag `v3.5.0`: `src/pow.ts` (`createChallenge`, `verifySolution`, `PasswordBuffer`), `src/algorithms/pbkdf2.ts`, `src/helpers.ts` (`canonicalJSON`, `sortKeys`), `src/types/index.ts` (`Challenge`, `ChallengeParameters`, `Payload`, `Solution`), `src/Widget.svelte`, and `MIGRATION-v2.md` (read them with `gh api repos/altcha-org/altcha/contents/<path>?ref=v3.5.0`).

## Global Constraints

- Package: `altcha@3.5.0` exactly (verified 2026-11-01: repository github.com/altcha-org/altcha, published 2026-10-22, no install script; one dependency `hash-wasm@4.12.0`, github.com/Daninet/hash-wasm, 2024-11-19, no install script). Install with `yarn add altcha@3.5.0 --ignore-scripts`; the lockfile must only gain `altcha` and `hash-wasm` from `registry.yarnpkg.com`. Install nothing else.
- Challenge format (v2 protocol): `{ parameters: { algorithm, nonce, salt, cost, keyLength, keyPrefix, expiresAt }, signature }`. `algorithm` = `PBKDF2/SHA-256`, `nonce` and `salt` = 16 random bytes as lowercase hex, `keyLength` = 32, `expiresAt` = Unix seconds, now + 300. Probabilistic mode (no `counter`, no `keySignature`).
- `signature` = lowercase hex `hash_hmac('sha256', canonical JSON of parameters, ALTCHA key)`. Canonical JSON = keys sorted recursively, keys with null/absent values left out, `json_encode(..., JSON_UNESCAPED_SLASHES | JSON_UNESCAPED_UNICODE)` (JS `JSON.stringify` does not escape `/`, and `PBKDF2/SHA-256` contains one). Integers stay integers.
- Derived key: `hash_pbkdf2('sha256', nonceBytes . pack('N', counter), saltBytes, cost, 32, true)`, the counter as a big-endian uint32 appended to the nonce bytes (`PasswordBuffer`, mode `uint32`).
- Payload the form posts as `altcha`: base64 of `{ challenge: { parameters, signature }, solution: { counter, derivedKey, time } }`.
- The ALTCHA key stays the existing one (`Altcha::getKey()`, SecretBox, `ALTCHA_HMAC_KEY` constant): no new secret.
- No third-party request, no cookie: keep `setCookie` unset, no `verifyUrl`, and set `humanInteractionSignature: false`, so the widget does not even record pointer and keyboard samples. The privacy text must stay true; adjust its wording only if the visitor-facing description changes ("a small calculation" → still accurate).
- Comments in English; visible strings translated in `fr_FR.po` (vouvoiement, plain space before ":" as the file does); `.pot` regenerated; `msgfmt -c --statistics` with 0 fuzzy and 0 untranslated.
- Commits: Conventional Commits in English, no attribution, one per task at least. No tag, no push.
- Checks after every task: `php83 /opt/homebrew/bin/phpunit --display-phpunit-deprecations`, `source ~/.nvm/nvm.sh && nvm use 20 && yarn test:js && yarn build` (commit `assets/dist`), and from `/Volumes/Samsung_T5/Freelance/twin-3d`: `php83 /opt/homebrew/bin/wp eval-file /Volumes/Samsung_T5/Freelance/lcmt-dev-mailer/tests/integration/run.php`.
- Never read `.env*`, `wp-config.php` or key files, never print the ALTCHA key.

## Review Focus

1. **Canonical JSON mismatch between PHP and JS**: any difference (escaped slash, key order, a float, an absent key) makes every signature invalid. Pinned by a fixture produced by ALTCHA's own `altcha/lib` (Task 2).
2. **A bot sending a cheap payload**: the widget's test payload `{challenge: null, solution: null, test: true}`, a counter of 0 with a made-up key, a solution for a lowered `cost` or shorter `keyPrefix` (the signature covers them), an expired or reused challenge, a v1-format payload. Each must fail (Task 2 tests).
3. **Pages served from a full-page cache** with the 2.7 markup (`challengeurl` attribute) next to the new script: the form must still get a proof (Task 1).
4. **A slow phone**: the chosen difficulty must stay under a few seconds on a mid-range phone, and the form handler's 30 s timeout must not fire (Task 3 calibration).
5. **Server cost per check**: verification runs one PBKDF2 at `cost` iterations per submission; a bot flooding the endpoint with fake payloads must not make it expensive. Reject on signature and expiry before deriving the key (Task 2).
